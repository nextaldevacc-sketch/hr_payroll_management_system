## PART A — Bug sweep

A1. Static scan (scripts/audit-ui-static.mjs, output docs/reports/BUG-SWEEP-STATIC.md). Scan frontend/src for: onClick/onSubmit handlers that only close a drawer/modal or do nothing; empty or missing handlers; console.log-only handlers; `href="#"`; TODO/FIXME/"coming soon"/"not implemented"; alert(); setTimeout used to fake success; hard-coded demo data or mock arrays rendered in UI; catch blocks that swallow errors; buttons with disabled that can never become enabled; routes in the sidebar with no page. List every finding with file:line and classify REAL / FAKE / INTENTIONAL. Fix all FAKE ones by wiring the real feature, or remove the control if the feature is out of scope (and say so).

A2. Dead-click crawler (scripts/audit-ui-crawl.mjs, Playwright, TEST database only, output docs/reports/BUG-SWEEP-CRAWL.md and .json). For EACH role (COMPANY_ADMIN, HR_MANAGER, HR_OFFICER, HR_OFFICER scoped to Visa 02, PAYROLL_OFFICER, GM, FINANCE, DEPT_MANAGER, EMPLOYEE): log in through the login page, visit every route the sidebar shows, then click every visible button, tab, menu item, quick action, table row action and drawer/modal trigger (skip only truly destructive ones in a separate list that A3 covers). After each click record: did the DOM change, did a network request fire, did the URL change. Flag as BUG: dead click (nothing happened), console error, any 4xx/5xx network response (a 403/404 after a click = visibility mismatch), literal "undefined"/"null"/"NaN"/"[object Object]", raw error codes shown to the user, untranslated English in Arabic mode, horizontal overflow on 390px. Every flagged item must be fixed or listed in NOT FIXED. The crawler must exit non-zero if any BUG remains.

A3. Visibility vs permission matrix (scripts/audit-role-matrix.mjs, output docs/reports/BUG-SWEEP-ROLE-MATRIX.md). Build a table: for every backend route, the roles it allows (read the route middleware and service checks, not guesses) versus whether each frontend control that calls it is visible to each role. Any control visible to a role that the backend refuses, or hidden from a role that is allowed, is a bug. Fix by deriving frontend visibility from shared/src/constants/permissions.js (canAccess) everywhere; no hand-written role arrays in components. Also confirm Company Admin can only reach Settings, Users & Roles and Audit (spec 5.3), and HR Officer never sees salary amounts.

A4. Forms and file inputs. For every file input in the app (compliance documents, employee documents, me/documents, leave attachments, company logo, biometric import, anywhere else grep finds type="file"): open it through the UI, attach with setInputFiles, submit, assert the result. Add these as workflow steps (UI only).

With a database that has only a company and its Company Admin, open every screen as Company Admin and as each other role (create them through the UI in the Part B test).
