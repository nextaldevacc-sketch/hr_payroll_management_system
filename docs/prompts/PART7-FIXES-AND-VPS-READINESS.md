PART C — VPS deployment kit (Ubuntu 24.04 LTS, Docker Compose, single VPS, domain with HTTPS)
======================================================================
Design (do not change without a stated reason): browser -> Caddy (automatic Let's Encrypt TLS, HSTS, security headers, gzip) -> frontend (Next.js `next start`, port 3100 internal) and API (Express, port 5000 internal) on the SAME origin (/api/v1 proxied by Caddy; the existing NEXT_PUBLIC_API_URL=/api/v1 stays) -> PostgreSQL 16 in a private Docker network with NO published port. Only ports 80 and 443 are public.
C1 FILES (all in the repo):
  - backend/Dockerfile and frontend/Dockerfile: multi-stage, `npm ci`, non-root user, minimal base image, no dev dependencies in the final image, HEALTHCHECK, no secrets baked in, frontend built with `next build` (fonts self-hosted per A3), Prisma client generated in build.
  - docker-compose.prod.yml: services caddy, web, api, postgres, backup. Named volumes for postgres data, document storage (backend/storage) and Caddy data. restart: unless-stopped, healthchecks, depends_on healthy, resource limits, log rotation, read-only root filesystem where possible, no `ports` on postgres/api/web.
  - deploy/Caddyfile: domain from env, reverse proxy rules, HSTS, X-Content-Type-Options, X-Frame-Options/frame-ancestors, Referrer-Policy, Permissions-Policy, request size limit matching upload limits, access log without query strings or PII.
  - .env.production.example: every variable with a comment, safe placeholders, no real secrets, plus a generator script scripts/gen-secrets.mjs that prints strong JWT_SECRET, DOCUMENT_ENCRYPTION_KEY and DB password.
  - scripts/preflight-prod.mjs: checks an env file against the Part B2 rules before deploy and exits non-zero on any problem.
  - deploy/deploy.sh (idempotent): pull, build, `docker compose ... up -d`, `prisma migrate deploy` (never reset), wait for health, run the smoke test, print the result; deploy/rollback.sh to return to the previous image tag and restore notes.
  - deploy/backup.sh and deploy/restore.sh: nightly pg_dump (custom format) + tar of the documents volume, encrypted with a passphrase from env (age or gpg), 14 daily + 8 weekly + 6 monthly retention, a copy pushed to a second location when configured (S3-compatible or rsync target, optional), and a scripts/verify-backup.mjs that restores the latest backup into a scratch database and runs check-integrity. Document that the encryption key and the backup passphrase are stored separately from the VPS: losing DOCUMENT_ENCRYPTION_KEY makes stored documents unreadable.
  - deploy/harden-vps.sh (run once as root on a new server, Ubuntu 24.04): create a non-root deploy user, SSH key-only login, disable root and password SSH, UFW allowing only 22 (rate limited), 80, 443, fail2ban, unattended-upgrades, Docker install from the official repo, time zone UTC with app jobs in Asia/Dubai, swap if RAM < 4 GB. Read-only explanation comments for every step. Must not lock the owner out: print a warning and require a confirmation before disabling password SSH.
  - scripts/smoke-test-prod.mjs <base-url>: asserts HTTPS and redirect from HTTP, HSTS and security headers present, /api/v1/health OK, /api/docs not reachable, login page loads with fonts from own origin, cookie flags HttpOnly/Secure/SameSite on login, wrong password lockout works, an unauthenticated API call is 401, response bodies contain no stack traces, DB port is closed from outside (report the port-check method used), Postgres not publicly reachable.
