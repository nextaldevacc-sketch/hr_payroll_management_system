# PART 7 ADDENDUM — gaps found for a real production launch

Read together with docs/prompts/PART7-FIXES-AND-VPS-READINESS.md. Same global rules (never weaken or skip a check; real command output only; NOT DONE list with reasons; commit per part). Do these items inside Part B (items E1–E4) and Part C (items E5–E7).

E1 REAL EMAIL. backend/src/lib/mailer.js is a fake: it only writes JSON files to storage/email-dev/ and logs "Sent email to ...". Nothing is ever delivered, so in production invites, temporary passwords, document-expiry reminders, payslip alerts and password resets would reach nobody. Implement a real SMTP transport (nodemailer) selected by env (SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASS, SMTP_SECURE, MAIL_FROM). In NODE_ENV=production the dev file transport must be OFF, startup validation (validateEnv) must refuse to start without SMTP settings unless MAIL_MODE=disabled is set explicitly, and the log line must say "sent" only after the SMTP server accepted the message (otherwise log "failed" with the error, never the body). Add retry with backoff and a persisted outbox table (status queued/sent/failed, attempts, last_error) processed by a job; failures must be visible to the Company Admin (Settings page "Email delivery") and the invite screen must show the copy-link / one-time-password fallback when sending failed. English and Arabic templates, branded, with no salary figures in any email. Test with an in-process SMTP test server (devDependency smtp-server) that actually receives the message; assert recipient, subject, link and that nothing sensitive is in the body.
E2 NO SECRETS ON DISK. In development the email-dev JSON files contain invite tokens and temporary passwords in plaintext. In production no such file may be written. In dev/test keep it but add the folder to .gitignore and document it. Add a test that production never writes to storage/email-dev.
E3 PASSWORD RESET AND INVITE FLOWS END TO END. Verify (UI steps through the real login page): forgot-password sends an email with a single-use, expiring link; reset invalidates all sessions (token_version); the reset message and timing are identical for known and unknown emails; an invite link is single-use and expires; HR facts alone can never reset a password or MFA (SEC-4). Fix anything that fails.
E4 NIGHTLY JOBS AND ALERTS BY EMAIL. Document expiry reminders (90/60/30), approval requests and payslip-ready notices must use the outbox; confirm idempotency (no duplicate emails on a second run) with tests. The deploy kit's backup job must email the Company Admin / ops address on failure.
E5 SPF/DKIM/DMARC NOTES in docs/DEPLOY-VPS.md: exact DNS records to add for the chosen mail provider and a test that sends a message and shows the headers (owner runs this step); state that the email provider is a sub-processor that must be listed in the data-processing agreement and located in the UAE for real client data if possible.
E6 PERFORMANCE SANITY. Run scripts/benchmark-p95.js (or a new script) on the production build with 500 employees × 12 months of generated test data: employees list, payroll calculation for 500 employees, SIF generation, payslip PDF, dashboard. Report p95 timings and fix anything above 3 s for list screens or above 60 s for a full 500-employee payroll calculation. Remove the generated data afterwards.
