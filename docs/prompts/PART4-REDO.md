## Hard rules for the workflow runner (all of 4A–4C)
1. Rewrite `scripts/verify-workflows.mjs` as a **step runner**. Each step = `{ wf, no, role, email, action, expect }`. For every step: log in as that user (log out between different users), do the action through the UI, then **assert** the expected result. If an element is missing or the assertion fails → the step is **FAIL**, the run continues to the next workflow, and the report shows FAIL with the error. **No `if (await x.count())` skips. No API shortcuts for actions** (API calls are allowed only to read back and assert).
2. Screenshot **every step** to `docs/reports/screenshots/workflow/<wf>-<no>-<role>.png`. Assert on each page: no "undefined", "null", "NaN" text; no "AED" for non-salary roles.
3. Each run starts from a fresh demo DB (`migrate reset` + seed) on the TEST database URL copied for this run — never the demo DB. Use new records created by the run (e.g. a new employee "Test Joiner <timestamp>") so seeded data is not modified.
4. `docs/reports/workflow-verification.md` is **generated by the runner** from its results (step table: wf, step, role, action, expected, actual, PASS/FAIL, screenshot). No hand-written claims.
5. Platform admin is disabled: never log in as platform@nextal.ae.
6. Fix every FAIL in the app (not in the test) until all steps pass; list each fix in the report's "Defects found and fixed" section.
